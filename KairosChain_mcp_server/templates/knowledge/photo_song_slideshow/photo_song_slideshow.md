# 写真から歌とスライドショーを作る

旅行や山歩きの写真の束から、その日の歌詞を書き、利用者が音楽生成サービス（SUNO など）で曲にし、
その曲に合わせて写真が拍ごとに切り替わり、歌詞が歌に合わせて出るスライドショーを作る手順。
一度通しで作り、別の作業者に「この手順あり／なし」で同じ依頼をこなさせて比べた結果から書いている。

## いつ使うか

- 「この写真で歌を作りたい」「グループの写真でスライドショーを」「曲に合わせて写真を流したい」
- 写真が WhatsApp のグループに散らばっていて、まず取り出すところから始まるとき
- すでに曲（mp3）と写真があり、拍と歌詞を合わせた動画だけ欲しいとき（途中の段階から入ってよい）
- 「エモい MV に」「エフェクトも入れて」「誕生日の MV を」のように、写真を順に出す以上のもの（光の効果、動き、ミニキャラ、動画）を求められたとき → § MV 版

**使わない場面**: 撮った動画の編集、曲そのものの生成（この手順は歌詞までを書き、曲は人が作る）、
写真の補正。

## 全体の流れ

```
写真の入口                写真を見る                  歌詞                      曲（人が作る）
WhatsApp から取り出し ─┐  抜き出し 16 枚          →  事実を聞く → 歌詞・題・  →  SUNO などで生成
フォルダの写真 ────────┴→ 一覧画像（24 枚/枚）        Style 案                   mp3 を置いてもらう
                          同じ写真の二重取りを探す                                    │
スライドショー  ←  確かめる  ←  描き出す  ←  歌詞の時刻  ←  並び順と拍割り  ←  拍を測る ←┘
HTML と MP4        静止画・振動    HTML / MP4    音声認識＋突き合わせ  内容で並べる        BPM・頭拍・盛り上がり
```

描き出しには二つの道がある。拍ごとに写真を切り替えるスライドショー（段階 5・7）と、場面ごとに効果と動きを作り込む MV 版（§ MV 版）。
どの段階から入ってもよい。各段階の出力（写真フォルダ、`lyrics.txt`、mp3、`beats.json`、
`project.json`、`lyrics_timed.json`）が次の段階の入力になっている。

## 段階ごとの手順と、そこで判断すること

コマンドの `scripts/` と `assets/mv/` は、この L1 の中のフォルダを指す（instance では `.kairos/knowledge/photo_song_slideshow/` の下）。
作業はプロジェクトのフォルダ（写真・曲・設定を置く所）で行い、道具はそのパスで呼ぶ。以下の例では短く `scripts/…` と書く。

### 1. 写真を集める

WhatsApp Desktop（macOS）なら `scripts/whatsapp_media.rb`。チャットの記録をそのまま触らず、
一時フォルダに写してから読み、終わったら写しを消す（写しにはメッセージ本文が入っているため）。

```
ruby scripts/whatsapp_media.rb list Walkers        # 名前と、グループか 1 対 1 かだけを出す（相手の電話番号は出さない）
# WhatsApp を終了してから実行すると、記録の写しが確実に揃う（動いている間は、写している最中に変わったら写し直す）
ruby scripts/whatsapp_media.rb copy --chat "Saturday Walkers" --date 2026-06-14 --dest ~/Pictures/walk_2026-06-14 --videos --dry-run
```

- **記録の中身を確かめたいときも、自分で写しを作らない**。`list` と `--dry-run` で足りる。
  評価では、手順あり・なしの両方の作業者が確認のために自前の写しを作り、削除を拒まれて残した
- ファイル名は「送信時刻_通し番号」。**送信時刻は撮影時刻ではない**。送る人ごとにまとめて送られ、
  ある人の束は新しい順、別の人の束は古い順に届くことがある
- Mac に一度も落としていない写真・動画はファイルが無い。件数と送信時刻を利用者に伝え、WhatsApp で開いてもらう
- 送った人の名前はファイル名に入れない（この道具にその機能は無い）。連絡先の記録からは引けるが、名前が外に広がりやすい

### 2. 少ない費用で写真を見る

写真 1 枚を原寸で読むと 1,000〜1,600 トークンかかり、150 枚なら 15〜24 万になる。`scripts/survey_photos.rb` で:

```
ruby scripts/survey_photos.rb sample photos/ --out survey/sample      # 出力は写真のフォルダと別の所（重なると止まる）
ruby scripts/survey_photos.rb sheets photos/ --out survey/sheets
ruby scripts/survey_photos.rb dupes photos/
```

`survey/` には縮小した私的な写真が残るので、作業が終わったら消してよいか利用者に聞く。

- `sample` — 撮った順に並べて同じ枚数ずつの組に分け、それぞれから無作為に抜く（16 枚、約 1.7 万トークン）。歌詞の下書きにはこれで足りる
- `sheets` — 番号付きの縮小画像を 24 枚ずつ 1 枚にまとめる（150 枚で 7 枚。一覧画像 1 枚は写真 1 枚と同じくらいなので約 1 万トークン）。並び順を決めるときに使う。
  標識の文字（地名・標高）のような細部もここで拾えることが多い
- `dupes` — 同じ写真が別の大きさで二重に入っている組を探す。WhatsApp では圧縮版と原寸版が両方届くことがあり、
  一覧画像では「よく似た写真」に見えて区別できない。同じ写真は差が 0〜3、別の写真はふつう 15 以上

写真から読むのは、歌詞に使える**具体物**（乗り物の窓から見た景色、標識の文字、食べた物、天気や光、人の表情や仕草）と、
**一日の流れ**。

### 3. 事実を聞き、歌詞を書く

写真だけでは場所の名前・道のり・数字はわからない。推測で書かずに聞く。経路アプリの画面写真があれば、
距離・登り・下り・最高地点が読める。地名の綴りは標識の写真とも突き合わせる（言い間違いや、似た名前の別の場所がある）。
「ずっと見えていた山」「途中で起きたこと」のような、写真に写りきらない体験は本人からしか出てこない。
こういう話は歌詞の中心（サビや Bridge）に据える価値がある。

- **言語**: 既定は英語。利用者の指定があればそれに従う
- **形式**: `[Intro] [Verse 1] [Chorus] [Verse 2] [Bridge] [Verse 3] [Chorus] [Outro]`。
  繰り返すサビは**全文を書く**（空の `[Chorus]` だけだと繰り返されないことがある）
- **長さ**: 歌詞欄の上限（3,000 文字の版がある）に収める
- **Style 欄**: 短く。曲調・テンポ・楽器・声の 4 点で足りる（例 `feel-good boom-bap hip hop, 92 bpm, acoustic guitar loop, group chant chorus, male rap vocals`）
- **題**: サビの合言葉＋道のり、の形が収まりがよい。2〜4 案出して選んでもらう
- **確かめていない話は歌詞に入れない**。言い伝えや一般知識の数字を入れたいなら「未確認」と添えた差し替え行として別に出す。
  評価では、手順なしの作業者が一般知識の言い伝えを歌詞に入れていた
- 曲ができたら、mp3 を写真フォルダに置いてもらう

### 4. 拍を測る

```
ruby scripts/analyze_audio.rb song.mp3 --out beats.json
```

依頼した BPM を信じない（2〜3 BPM ずれることがある）。曲を 3 つの帯域に分けて音の立ち上がりを拾い、
候補のテンポを細かく詰めたあと、バスドラムの位置に直線を当てはめて拍の間隔と最初の拍を決める。
出力の `fit_scatter_ms`（当てはめのばらつき、20 ミリ秒未満なら安定）と、20 秒ごとの拍のずれの表を見る。
`drop_beat`（音が大きくなって曲が本格的に始まる拍）までは前奏で、表題と経路の札を置く場所になる。
テンポのわずかな誤差は曲の後ろほど積み重なる。評価では 0.1 BPM 未満の差が、3 分後に 0.14 秒の遅れになり、
最後の 35 秒は拍に合っていなかった。

### 5. 並び順と拍割りを決める（`project.json`）

並び順は**内容で**決める。一覧画像を見て、移動 → 登り → 休憩 → 頂上 → 下り → 到着、のような段に振り分け、
段の中は送信順を手がかりにする（新しい順で届いた束は逆にする）。`assets/project.example.json` が書式の見本。

- 写真 1 枚は 2 拍が既定。似た写真が続く所は 1 拍ずつの早送りにすると、全部の写真を曲に収められる
- 同じ写真の二重取り（`dupes` で見つけた組）は、利用者に聞いて片方を外すか、続けて 1 拍ずつにする
- 見せたい 1 枚（その日の象徴）は 4 拍
- 前奏の札の拍数の合計を `drop_beat` に合わせる（例: 表題 16 拍＋経路 20 拍＝36 拍）
- 最後の 1 枚は曲の終わりまで残り、締めの言葉が下 1/3 に出る。顔に文字をかぶせないため
- `ruby scripts/build_slideshow.rb project.json check` で溢れを確かめる（最後の 1 枚が 4 拍未満なら失敗にする）

### 6. 歌詞の時刻を取る

```
ruby scripts/align_lyrics.rb song.mp3 lyrics.txt --out lyrics_timed.json --words words.json \
     --recognizer whisper-cpp --model ~/models/ggml-large-v3-turbo.bin     # または --recognizer mlx --bin /path/to/mlx_whisper
```

音声認識は外部のプログラム（whisper.cpp の `whisper-cli`、または Apple Silicon 向けの `mlx_whisper`）を呼ぶ。
入っていなければ、入れてよいか先に聞く（モデルは約 1.6 GB）。
画面に出す文字は**利用者の歌詞そのもの**で、認識結果は使わない。認識は「各行がいつ歌われたか」を取るためだけ。
地名の聞き違い（小さな村の名前が似た英単語として聞き取られる）や数字（"nine-thirty" が "9.30"）は、
前後の語で位置が決まるので問題にならない。`FILLED` や `weak` と出た行だけ、利用者に聞いて確かめてもらう（作業者は音を聞けない）。
長い 1 行が 2 つの句で歌われているなら、`lyrics.txt` でその行を 2 行に分けてから流し直す。
`[Intro]` のような見出しと、`(yeah, yeah...)` のような合いの手だけの行は表示しない。
SUNO の歌詞欄から貼った `Title:` `Style:` の行も表示しない。各行には語ごとの時刻（`words`）も付く。MV 版はこれで一語ずつ出す。
空白で区切らない言語（日本語など）は、突き合わせは 1 文字ずつだが、表示の「語」は空白で分けるので 1 行がまとめて出る。
英語以外の歌詞では `--language ja` のように言語を付ける（既定は `en`）。
最初の語が聞き取れなかった行（数字や地名）は、聞き取れなかった語 1 つにつき 0.4 秒ほど早めに出す（前の行の終わりより前にはしない）。
`--words` の保存は同じ録音（ファイル全体の sha256 が同じ）のときだけ使い回す。曲を差し替えたら自動で認識し直す。
小声の部分（ささやく Bridge など）は、曲全体の 1 回の認識で丸ごと取りこぼすことがある。`FILLED` や `weak` が数行続いたら、
その区間を `--extra-pass 166,208` のように切り出して認識し直す（評価では 8 行すべて取れた）。
歌詞の語のうち聞き取れたのが 3 割未満なら、曲が歌詞と別物だと警告が出る。曲名の札（mp3 の title）も表示されるので、利用者に確かめる。

### 7. 描き出して確かめる

```
ruby scripts/build_slideshow.rb project.json html
ruby scripts/build_slideshow.rb project.json frames 12 60 106.8 205   # MP4 と同じ経路で静止画
ruby scripts/build_slideshow.rb project.json mp4
ruby scripts/check_motion.rb slideshow.mp4 --at 25 60 120
```

MP4 は、ImageMagick で写真 1 枚ごとに 1 枚の静止画（ぼかした背景＋写真、または表題・札）を作り、
ffmpeg がそれを 1 コマごとに小数点以下の精度で拡大し（`perspective`）、次の写真へ重ねて切り替え、
字幕と歌詞を字幕ファイル（ASS、libass で描画）から描いて、写真ごとの短い区間を書く。区間は再符号化せずにつなぎ、
最後に曲を入れる。中間ファイルは `work_dir` に残り、変わっていない区間は作り直さない。

- HTML は `slideshow.html#t=60` で 60 秒目を止めた状態で開ける。画面なしの Chrome で撮れば HTML 側も確かめられる
  （`--headless=new --screenshot=… "file://…/slideshow.html#t=60"`。`--virtual-time-budget` は付けない、下の「罠」）。
  止めた状態なので再生ボタンと薄い暗幕が写るのは正常
- 確かめる場面: 表題、経路の札、字幕の出る写真、歌詞が明るい写真に乗る所、最後の集合写真
- MP4 は `check_motion.rb` で振動が無いことを数字で見る（逆向きの動き 0 回、ばらつき 0.3 ピクセル未満）
- 音を出しての通し再生は、作った本人には確かめられない。報告では「確かめていない」と書き、利用者に見てもらう

### 8. 報告する

- 出来たファイルと場所、長さ、大きさ（WhatsApp で送るには 150 MB 前後は大きい。720p の軽い版を提案できる:
  `ffmpeg -i slideshow.mp4 -vf scale=1280:720 -c:v libx264 -crf 24 -c:a copy slideshow_720p.mp4`。
  `project.json` の大きさを変えて描き直すと、表題や札の文字の大きさが画面に対してずれるので、そちらは使わない）
- 推測で決めた所（並び順、最後の店がどこか、字幕の地名）を推測として書く
- 歌詞と写真の場面がずれている所（下の「既知の限界」）

## MV 版 — 効果と動きを作り込む

写真を拍ごとに出すのではなく、歌詞の一行ごとに場面を作る。光の効果、ぼけた光の粒、映画の黒帯、ミニキャラ、動画、
写真で作るハートなど。スロー〜ミドルテンポの曲（誕生日・記念日の歌）に向く。速い曲で拍ごとに切りたいならスライドショーのほうが合う。

```
素材                                  下ごしらえ                              台本                       確かめる              書き出す
写真・動画・生成背景・ミニキャラの一覧画像 → mv_assets.rb ─┐
歌詞・曲 → analyze_audio.rb ・ align_lyrics.rb ─────────────┴→ mv_data.rb → scenes.js を書く → mv_render.rb sheet → mv_render.rb mp4 --light
                                                                (data.js)    （場面の並び）      （数秒おきの静止画）   （原本・1080p・720p）
```

**仕組み**: `assets/mv/mv_engine.js` が「時刻 t の 1 コマ全体を描く」関数を持つ。ブラウザでは曲の再生位置を時計にして描き、
`mv_render.rb` は同じ関数を画面なしの Chrome で 1 コマずつ呼んで撮る。だから MP4 は、ブラウザで同じ時刻に止めた画面と同じになる。
再生中のブラウザでは、動画が最大 0.25 秒ずれることがあり、フィルムの粒の並びは毎回違う
（評価では、作り直した道具で描いた 46 コマ中 45 コマが元の版と画素単位で一致、残り 1 コマは文字のふちの 1,382 画素だけ違った）。
速さは毎秒約 13 コマ。5 分 14 秒の曲（9,432 コマ）で約 12 分。20 秒ごとに区切って書くので、止まっても続きから書ける。
ページ・場面・素材（`assets/` の中のファイル）のどれかを変えると、前の区切りは使われない。

**手順**

1. `mv_project.json`（見本 `assets/mv/mv_project.example.json`）に、写真のフォルダ・生成背景・ミニキャラの一覧画像・
   使う動画の区間を書いて `ruby scripts/mv_assets.rb mv_project.json`。
   - 生成背景とミニキャラの一覧画像は利用者が用意するもの（画像生成サービスで作るなど）。無ければ聞く。
     背景が無くても、場面の背景に写真の名前を使えば作れる。ミニキャラは無くてもよい
   - 元のフォルダには書き込まない。出力先と元のフォルダが入れ子なら、どちら向きでも止まる（大文字小文字の違いや別名リンクも見抜く）。
     元のファイルが出力先の中にあっても止まる。`out` は `assets` のままにする（`mv.html` は `assets/data.js` を読む）
   - 写真の名前は、ファイル名から拡張子を除き、英数字・`_`・`-`・`.` 以外を `_` にしたもの。二つが同じ名前になると
     （大文字小文字の違いだけでも、背景の `bg1` などとでも）止まる。利用者のファイルは改名しない。片方を `skip` にパスで書くか、
     利用者に聞いたうえで別の所へ新しい名前で写し、写しを使う
   - 背景は、背景のフォルダの png と jpg を名前の順に `bg1`, `bg2`, …。`replace` で「何番目をどのファイルに」と差し替えられる
   - ミニキャラは `名前_01` から、一覧画像の上の段から、段の中は左から順に番号が付く。どれがどのポーズかは切り抜いた画像を
     一覧にして見る（`-label` はファイルの前に置く。後ろに置くと名前が付かない）:
     `magick montage -label '%t' assets/stickers/*.png -background '#335' -geometry 200x200+4+4 stickers.jpg`
   - 動画は、使う場面の長さ×再生の速さより長く切り出す。短いと最後のコマで止まる（見本では 74.0〜84.6 秒、速さ 0.92 で約 10.5 秒）
2. `ruby scripts/mv_data.rb --lyrics lyrics_timed.json --manifest assets/manifest.json --beats beats.json --out assets/data.js`
3. この L1 の `assets/mv/mv_template.html` をプロジェクトのフォルダに `mv.html` として、`assets/mv/mv_engine.js` をその隣に写し、
   `assets/mv/scenes.example.js` を手本に `scenes.js` を書く（見本の歌詞の書き出しは仮のもの。自分の歌詞の行に置き換える）
   `MV.start` の `duration` は曲の長さ（秒）、`audio` は `mv.html` から見た曲の場所に書き換える
4. `ruby scripts/mv_render.rb sheet mv.html 4` で 4 秒おきの静止画一覧を見る。直したら `stills mv.html 218.5 220` で個別に
5. `ruby scripts/mv_render.rb mp4 mv.html --audio song.mp3 --out mv.mp4 --light`。小さな修正の後は `--keep-outside 218,223`
   （その区間を含む 20 秒の区切りだけ描き直し、残りは最後に曲全体を書き出したときの作り置きから写す。16 区切り中 1〜2 区切りで、12 分が 1〜2 分になった）。
   試しに一部だけ書き出すなら `--from 165 --to 185 --out test.mp4`

**台本の決め方（ここが出来を決める）**

- **層を三つに分ける。** 離れて暮らす気持ちを歌う所は生成背景（想像の場面）。思い出を歌う所は実際の写真と動画。最後のサビと
  「Happy Birthday」は祝う場面。実写に切り替わる所に光漏れを置くと、聞き手にも「ここから本物」と伝わる
- **一行に一場面。** ゆっくりの曲では一行がほぼ一小節。切り替えは行の 0.3 秒前、重ねて変わる長さはふつう 0.9〜1.4 秒、
  ゆっくり移る所（Bridge の入り、夜明け、締め）は 1.6〜2.0 秒。硬い切り替え（間奏へ、祝う場面へ）は 0.3〜0.6 秒＋白い光
- **歌詞の中身から場面の型を選ぶ**（下の表）。歌われる「Happy Birthday」は歌詞として出さず、題字として描く（`lyrics.hide`）
- **二人の写真（主役の一枚）は各サビの最後の行と、締めに置く。** 締めでの再登場はかまわない
- **区間ごとの見た目**: 黒帯は Verse と Bridge、サビで開く。光の粒は昼の写真では 0.25〜0.3（多いと青空が霞む）、夜と締めは 0.6〜0.95。
  にじみは昼 0.17、夜と締め 0.3。光漏れは区間の変わり目に
- **ミニキャラは小さく（高さ 240〜380 ピクセル）、顔に重ねない。** 歌詞の一語に合わせて弾むように出し、祝う場面では半拍ずつ

**確かめること**（静止画一覧で見つかったもの。どれも一度ずつ起きた）

- 黒帯に顔が隠れる: 生成背景は顔が画面上端から 1 割ほどの所に来やすく、上の黒帯（高さ 136 ピクセル）に頭が入る → `PB` で黒帯の内側に収める
- ハートの窓から顔が外れる: 写真の端にいる人が切れる → `heartIris` に二つの顔の位置を渡す（写真を縮めて、二つの顔がハートの左右の膨らみに入る）
- 縦写真を全画面にすると空しか映らない: 注目点の高さを 0.55〜0.65 に下げる
- 携帯やポラロイドが黒帯の下に入る: 中身は 170〜910 ピクセルの間に収める
- 前の歌詞が間奏に残る: 行の終わりから 1.0 秒で消す
- 粒子が飛ぶ: 0.1 秒離れた 2 コマを並べて見る。見えない粒子を飛ばす前に乱数を引かないと、一つ消えるたびに残り全部の位置がずれる
  （評価では音符が 0.32 秒ごとに 4.7 秒間跳んでいた）
- 動画: 動画を含む 20 秒だけ試しに書き出し（`--from` `--to`）、動画の部分から隣り合うコマを数枚抜いて、動いていること・
  同じコマが続かないことを見る（`ffmpeg -ss 5 -i test.mp4 -fps_mode passthrough -frames:v 3 f%d.png`。
  `-fps_mode passthrough` が無いと最初のコマが二重に出て、止まって見える）
- 光漏れや粒子が跳ぶ: 種（乱数の始まり）を時計から取ると、種が変わる瞬間に位置が跳ぶ。見えない粒子を飛ばす前に乱数を引く、
  中心は端から端へ折り返さず揺らす（エンジンはそうしてある。場面を足すときも守る）

**大きさ**: 画面全体の粒子（フィルムの粒）は圧縮しにくく、原本（画質の指定 17）は 5 分 14 秒で 1.7 GB になった。
`--light` で 1080p（22）495 MB と 720p（24）68 MB も作る。人に送るのは 720p。

## 人に聞くこと・人が決めること

| 場面 | 理由 |
|---|---|
| どのチャットの、どの日の写真か | 名前の一部が複数のチャットに当たることがある |
| 地名・道のり・数字・その日の出来事 | 写真からは読めない。推測で書くと歌に残る |
| 歌詞の言語、題 | 歌うのはその人たちのグループ |
| 同じ写真の二重取りをどうするか | 「1 枚も削らない」と言われていることがある |
| 音声認識を入れてよいか | 環境への追加と約 1.6 GB のダウンロード |
| 公開するか | 友人の顔が写っている。グループ内なら問題ないが、ネットに出すなら全員の了解が要る |
| 生成背景・ミニキャラを用意してもらうか（MV 版） | この L1 は作らない。無くても写真だけで作れる |
| スライドショーか MV 版か | 速い曲で拍ごとに切るか、場面ごとに作り込むか（MV 版は書き出しに約 12 分、作り込みに数時間） |
| 画面に出す地名・日付・署名 | 事実を言い切る文字は推測で入れない。分からなければ「your morning / my evening」のように言い切らない札にする |
| 名前の出てこない素材（別のキャラの一覧画像など） | 使うなら脇役として使い、報告で使い方を書く |
| 曲の取り違え | 置かれた mp3 が歌詞と別の曲のことがある。曲名の札と歌詞の題を比べ、違えば聞く |

## 罠（実際に一度ずつ踏んだもの）

- **MP4 の振動**: 拡大の途中で、写真の幅・高さ・位置を毎コマ整数ピクセルに丸めると（縦横で別々に）、
  写真が不揃いに進み、横長・縦長に交互に伸びて震えて見える。HTML（ブラウザは小数点以下で動かす）では起きない。
  ffmpeg の `perspective` を `eval=frame` で使うと、1 コマごとに小数点以下の精度で拡大できる。
  測った値: 逆向きの動き 13 回中 4 回 → 0 回、ばらつき 1.14 → 0.03 ピクセル
- **振動の測り違い（3 つ）**: (1) `ffmpeg -ss <コマ番号/30>` を 1 コマずつ呼ぶと、時刻の丸めで 3 コマに 1 回前のコマを読む。
  連続するコマは 1 回の呼び出しでまとめて読む。(2) `-fps_mode passthrough` を付けないと最初のコマが二重に出る。
  (3) 画面の中央は拡大してもほとんど動かないので、中央で測ると雑音しか拾わない。左寄りの帯で測る
- **音声認識への手がかり文**: 手がかり（initial prompt）を渡すと、前奏の楽器だけの所で手がかりの文そのものが
  聞き取り結果として出てきた。手がかりなしの 1 回で全行が取れたので、渡さない
- **ImageMagick の `jpeg:size`**: 大きな写真の読み込みを速くする指定だが、小さな画像は逆に 2 倍に拡大して読む。
  元の大きさで指定した切り抜き座標がずれる。切り抜く画像には使わない
- **ImageMagick の `-gravity` は残る**: 背景づくりで `-gravity center` を指定すると、後の `-crop` の位置が中央基準になる。
  切り抜きの前に `+gravity` で戻す
- **作り置きの見分け方**: 中間ファイルを「元の写真と設定が同じなら再利用」で判定すると、作り方を直しても古い出来損ないが使われ続ける。
  作るときのコマンドそのものを鍵にする
- **1 行だけの帯を切り出す**: 動画の色の形式（yuv420p）は高さ 1 で切れない。先に灰色へ変換してから切る
- **HTML の属性の引用符**: `style="background-image:url("…")"` は内側の `"` で属性が切れ、背景が黙って消える。`url('…')` にする
- **重なり順**: 写真ごとに重なり順の番号を振ると、字幕や締めの文字がその下に潜る。写真の層を `isolation: isolate` の箱に閉じ込める
- **明るい写真の上の歌詞**: 白い砂利や雪の上では読めない。歌っている間だけ画面の下をうっすら暗くする
- **経路の札と歌詞**: 札の画像が画面下まであると歌詞とぶつかる。札は高さ 84 %、中心 45 % の位置に置く
- **字幕の文字の大きさ**: ASS の文字の大きさは行の高さで、CSS や ImageMagick の大きさ（文字の幅の基準）より約 1.33 倍大きく指定して揃う
- **元の写真を出力で潰す**: `ls … | xargs magick montage … OUT.jpg` は、xargs がファイル名を OUT の後ろに足すため、
  最後の写真が出力先になって一覧画像で上書きされた（2 枚失った。写真アプリから書き出し直すしかない）。出力が最後の引数になる
  コマンドにファイル一覧を xargs で渡さない。最初の失敗「unable to open image OUT」は出力欄が入力に使われた印なので、やり直す前に元を確かめる
- **別の曲**: フォルダの mp3 が歌詞とは別の曲で、61 行中 0 行しか聞き取れなかった。mp3 の title は別の題だった
- **SUNO の指示は守られるとは限らない**: 「[Music drops to piano]」と書いた Bridge も、サビと同じ音量（約 −16 dB）だった。場面の強弱は指示ではなく測った音量で決める
- **画面なし Chrome の `--screenshot` に `--virtual-time-budget` を足す**: 動画と音声の要素がある MV ページで終わらなかった（一度）。
  この組み合わせは使わない。MV 版は `mv_render.rb`（Chrome の DevTools 経由）で撮る
- **file:// のページは JSON を読み込めない**: 歌詞と素材の一覧は `data.js`（スクリプト）にして読み込む
- **ミニキャラの切り抜き**: 白い背景をふちから塗りつぶして消す（ゆるさ 6 %）。余白に隣のキャラがはみ出すので、そのキャラ自身の画素だけ残す。
  くっついて描かれた 2 体は 1 枚になる（27 体中 1 枚）。体と腕の間に閉じた白は消えない

## 既知の限界

- **歌詞と写真の場面は合わせていない**。写真は道のりの順なので、「電車」と歌う所で別の景色が出たり、
  象徴の 1 枚が歌われる時刻とずれたりする。直すなら、要の写真をその歌詞の行の時刻に留め、
  間を道のりの順で詰める形になる（まだ作っていない。必要になった時点で作る）
- WhatsApp の取り出しは macOS 版だけ。データベースの形は WhatsApp の更新で変わりうる
- HTML は写真フォルダの写真を参照するので、単体では渡せない。人に送るなら MP4
- MV 版の字体は macOS のもの（Hoefler Text、Snell Roundhand、Didot、Avenir Next）。ほかの環境では代わりの字体になる
- MV 版で歌詞の行が替わる瞬間、前の行と次の行が同じ位置で 0.4 秒ほど重なって見える（未対応）
