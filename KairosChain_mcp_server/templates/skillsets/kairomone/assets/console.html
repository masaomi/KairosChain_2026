この画面について

端末でだけ行うこと

ホストの L0 が変わったとき、それを受け入れるかどうかは、あなた自身がこのプロジェクトのフォルダーの端末で判断します。Claude には実行させないでください。

ruby .kairos/skillsets/kairomone/scripts/kairomone.rb l0 rebaseline --reason "…"

バックアップからの復元は、Kairomone の道具（kairomone_backup）からは、どのモードでもできません。コマンド行の復元は端末を必要としますが、擬似端末を開くシェルの命令なら実行でき、確認ありでは、Claude Code が読み取りだけと判断した命令を除き、その命令は実行前に問われます。復元は端末の Claude Code セッションで行ってください。

この画面の弱さ

  • 学習には curl が要るので、Claude はシェルを使えます。シェルはあなたと同じ権限で動き、相棒のファイル（.kairos/kairomones/ の下、0.8 より前に作った相棒は .kairos/kairomone/ の下）を書き換えることも、コンソールを止めても動き続けるプロセスを作ることもできます。相棒のファイルにシェルで触れないよう Claude を縛っているのは、Kairomone の決まり（SKILL.md）です。
  • 起動時の点検が見るのは Kairomone のパッケージだけです。同じデータの場所にある別の SkillSet は同じサーバーの中で動き、Kairomone の道具を置き換えることができます。
  • 確認ありでも、Claude Code が「読むだけ」と判断した命令は問われずに実行されます（実行したことはこの画面に出ます）。auto では何も問われません。
  • 端末のセッションでは、許可の問いに答えるのは Claude が入力できない端末です。この画面はそれより弱い仕組みです。この画面の合言葉は Claude に渡していませんが、あなたと同じ権限で動くプロセスが探せば、読める可能性はあります。

この画面が書かないもの

この画面は相棒の記録を自分では書きません。書き込むのは、Claude が Kairomone の道具を使うときだけです。表示する Kairomone を切り替えても、変わるのはこの画面の表示と、置く文に入る識別子だけです。
