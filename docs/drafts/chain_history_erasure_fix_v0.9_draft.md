## 1. 消える経路は 2 つ

`save_chain`（`chain.rb:74`）はファイル全体の書き直しで、書く前にディスクの現在の
姿を確かめない。

```
経路 A — 古い姿の上に書く（実測で再現）
  甲と乙が長さ 2 で読み込む → 甲が積んで保存（ディスク 3）
  → 乙が積んで保存 = 記憶の 2＋1 で上書き（ディスク 3）→ 甲のブロックが消える。例外なし

経路 B — 姿を知らないまま書く（実測）
  台帳が壊れている／読めない → load_blocks が nil → genesis から建て直し
  → 次の保存が 687 を 2 で上書き。add_block は Block を返し、成功に見える
```

## 2. INV-D — ディスクの末尾に積む。記憶にある列で置き換えない

> 保存は、そのときディスクにある列の末尾にブロックを足すことしかできない。
> 記憶の中の列でディスクの列を置き換えない。ディスクの列が判らないときは、積まない。

前提: 台帳は局所の filesystem（`flock`。darwin 実測、Linux は実装時に同じ反証）。
backend が答える経路は絶対経路 — **これは前提ではなく ⓪ の拒否で執行する**（R8）。

### 積む手順

```
⓪ (い) の旗を見る。立っていれば ChainStateError（鍵を取る前 — 取ってからでは
   flock の自己 deadlock になる。R8 cursor）
   backend の答えが絶対経路でなければ Storage::Error（CWD 依存の鍵は排他の静かな
   喪失。R8 実測: 相対の答えは今日素通りする）
① 鍵を取る（答えの経路 + ".lock"。親ディレクトリと鍵ファイルはここで作られることが
   ある。open / flock の失敗は Storage::Error に包む）
② ディスクを読み、5 値（§ 3）に分類する
③ 状態が「読めた」でも「無い」でもなければ ChainStateError。台帳には何も書かない
④ 土台: 読めた → その列 ／ 無い → genesis 1 個だけの列（→ L-7）
⑤ 鍵の内側で、④ の末尾の上にブロックを組み（番号 = 末尾+1、前 hash = 末尾の hash）、
   「④ の列 ＋ 新ブロック」を書く                    ← 経路 A が閉じる
⑥ 保存が例外を上げなければ、記憶の列を差し替え、状態を「読めた」に進める
⑦ 鍵を放し、旗を降ろす（同じ ensure。旗を降ろすのは**旗を立てた呼び出しだけ** —
   ⓪ で拒否された入れ子が外側の旗を消してはならない。R8）
```

状態と列は**積みに成功したときだけ**進む。③ の拒否や ⑤⑥ の例外では動かさない —
その instance の状態は「最後にディスクを読んだ時点の真実」であり、書きの成功時のみ
「書いた瞬間の真実」になる。instance を持ち続ける読み手（`mmp/chain_adapter.rb:26`）
には古くなりうる（R8。分割 ③ の census に記載済み）。⑥ の差し替えは MRI では
参照の入れ替えで安全（他処理系は保証外 — 実装の注記に落とす）。

genesis は決定的（`block.rb:32-40`。全欄が定数）。

### 例外は 2 つだけ

| 例外 | 誰が | 意味 |
|---|---|---|
| `ChainStateError`（属性 `state` に 5 値のどれか） | `Chain` | ⓪ の旗・③ の拒否・INV-G の契約拒否 |
| `Storage::Error`（原因例外を包む） | backend と、鍵・経路の検査を包む `Chain` | 読み書き・鍵の I/O 失敗、絶対経路でない答え |

段階（①〜④ か ⑤⑥ か）はクラスからは判別できない — **意図した畳み込み**と宣言する
（R8）。呼び手の規則は単純になる: `ChainStateError` = 何も書いていない、
`Storage::Error` = **書けたか不明、読み直して確かめる**。
2 クラスとも `StandardError` の子として新設（既存の `rescue StandardError` に
握られる — それは L-4 の既知の穴で、この設計の外）。

### 保存の帰結は 3 通り

| 帰結 | 意味 |
|---|---|
| Block が返った | backend が書き終えて例外なし。電源断まで残るかは別（L-5） |
| `ChainStateError` | 台帳は触っていない（鍵ファイルと親ディレクトリは作られうる） |
| `Storage::Error` | **書けたか不明**。「書けていない」と読んではならない |

書き側の契約: `save_all_blocks` は失敗を `false` で返すのをやめ `Storage::Error` を
上げる（いまの `file_backend.rb:57-59` は全例外を `false` に潰す）。

### 鍵の規則（3 つ）

**(あ)** 鍵は台帳とは別のファイル（台帳自体に掛けると新規インストールが永久に書けない
— R3 実測）。**(い)** 入れ子は全面禁止。旗は 1 bit、置き場は
`Thread#thread_variable_set / get`（fiber をまたぐ。`Thread#[]` は fiber 単位 —
`daemon/execution_context.rb:10`）。**(う)** 鍵ファイルを消さない（消されると別 inode に
鍵が掛かり排他が黙って失われる — 実測でブロック喪失を再現）。反証は変異の向き
（⑦ に unlink を足すと検査 2・3 で喪失が再現する）。

`flock` は同一プロセス内でも別ファイルオブジェクトを互いにブロックする（darwin
実測）ので `Mutex` は不要。取得に締め切りは無い — L-8。

## 3. INV-E — 状態を運ぶのは `load_state` であって、ブロックの列ではない

> 台帳の状態は、読む側が必ず通る 1 つの入口が運ぶ。

**`Chain.new` は例外を上げない。** backend の `Storage::Error` は `Chain` が
**その 1 クラスだけを**受けて「読めない」に落とす（いまの `chain.rb:103-106` の
`rescue StandardError` を**この狭い受けに置き換える** — 全部消すのではない。
全部消すと EACCES が素通りして「上げない」が崩れる — R8 実測）。
`chain.rb:20` の `|| [Block.genesis]` は除去。
状態の公開名は **`Chain#load_state`**（public。11 箇所と検査が読む入口）。

### 5 値と述語

**分類は、backend の配列から再構築したブロック列（`chain.rb:108-117` の
`parse_timestamp` を通った後）の上で走る**（R8 — 生の配列の上では時刻が文字列のままで、
述語 1 が字義どおりだと実台帳を弾く。再構築後なら実台帳は全述語を通る — 実測済み）。
述語 3 の hash は再構築時に再計算された値どうしの比較である（保存欄の hash は
読み込みで捨てられる — L-1 の同族）。

| 状態 | 述語 | 積めるか |
|---|---|---|
| 無い | backend が nil を返した | 積める |
| 読めない | backend が `Storage::Error` を上げた | 積めない |
| 空 | 配列が返り、0 個 | 積めない |
| 壊れている | 配列が返り、下のどれかが落ちる（**述語評価中の例外も含む** — 全域） | 積めない |
| 読めた | 配列が返り、次のすべてが通る | 積める |

1. **ブロック 0 は正規 genesis と同一**（`block.rb:32-40` の 5 欄すべて。比較の
   実装形は実装の裁量、対象欄は設計が固定）
2. 番号は 0 から 1 ずつ連続（先頭が 0 でない — 例 `[5,6,7]` — や重複は「壊れている」）
3. 各ブロックの前 hash が直前の（再計算された）hash と一致
4. **ブロック 1 以降**の Merkle 根が data からの再計算と一致（genesis の
   merkle_root は定数の埋め草 `0…0` で、再計算値 `89eb0ac0…` と一致しない — 実測。
   ブロック 0 は述語 1 が固定する）

`valid?` は「状態 = 読めた」の別名。

### backend の読み契約（**読み側も範囲に入る** — R8 の最大の訂正）

v0.8 は §7 の「入る」に書き側しか載せず、読み側が現状のままだと **0 バイトも壊れた
JSON も nil に潰れて「無い」に化け、genesis から建て直される — 経路 B が生きたまま**
だった（R8、3 体が実測で収束。`file_backend.rb:41-44` の rescue が
`JSON::ParserError`/`ArgumentError` を nil にしている）。対称に固定する:

> **`FileBackend#load_blocks`（読み側、範囲に入る）**: nil を返すのは**ファイルが
> 無いときだけ**。開けない・parse できない（0 バイト含む）は `Storage::Error` を
> 上げる（原因を包む）。

判別線は v0.8 と同じ — **契約（§ 4 の問い）を宣言した backend の返しだけを
3 形で読む。宣言しない backend の読みは、返しが何であれ「読めない」**（機能喪失は
L-9）。

### 読む側の報告の形

報告には状態の欄があり 5 値のどれかが入る。長さは「読めた」のときだけ意味を持つ。
`Chain#chain` は「読めた」以外は空の凍結配列、`latest_block` は nil — 組む側は状態を
先に見る。rescue の枝の形（状態欄を捏造しない）は実装レビュー項目（`Chain.new` が
上げない以上、台帳状態では到達しないため）。読み手は鍵を取らないので、書き直しの
最中の読みは一時的に「読めない／壊れている」になりうる — fail-closed の無害な過渡で、
次の読みで治る（instance を持ち続ける読み手を除く。上記）。
新規インストールの報告は「台帳はまだ無い」 — 同じ `valid?`→FAILED 導出が
`chain_verify.rb:47-51`・`admin/router.rb:370-374`・`introspection_check.rb:100` の
3 箇所にある。

## 4. INV-G — 契約を宣言しない backend では積まない

> 宣言しない backend の下では、`Chain` は積みを拒み（`ChainStateError`）、読みも
> 「読めない」と解釈する（§ 3）。

`sqlite_backend.rb:124-127` の `save_block` は `INSERT OR REPLACE`（`:135-143` の
`save_all_blocks` はそれを transaction 内で回すだけ）で列を切り詰めない — file 前提の
手順が当たらない破損経路。問いは 1 つ「あなたの台帳の**絶対経路**を言いなさい」。
既定の実装は答えない。`FileBackend` は `blockchain_file`（`:147`、public）で答える。

（`:133-135`）— L-4 の実例。

## 6. 閉じないもの

- **L-1（いちばん重い）**: 短い・分岐した・内部的に正しい履歴は見分けられない。
  保存 `hash` 欄の書き換えに加え、**hash の材料になる欄（時刻など）の書き換えも、
  読み込み時の再計算が自己整合に「正規化」してしまい、次の保存で定着する**
  （R8 codex — 同族として明記）。積みは「そのときの末尾」への保証であり、切り詰め後の
  最初の正当な積みは切り詰められた履歴を保証する。署名された外の証人が要る。
  **予防も認識も無いまま残る。**
- **L-2**: 鍵を無視する書き手・別名経路（ハードリンク等）の書き手は止められない。
- **L-3**: 混入済み 14 ブロックは消せない。
- **L-4**: `add_block` 24 箇所の多くが握り潰す（`knowledge_provider.rb:838-864`、
  `safe_evolver` の両呼び手 `:133`/`:191`、`multiuser`、`file_backend.rb:47-51` の
  `save_block`）。新設 2 例外も `rescue StandardError` には握られる。是正は分割 ③。
- **L-5**: 中断・ENOSPC・電源断による切り詰め。耐久（fsync 系）と一時ファイル＋
  `rename` はここに束ねた後続変更。③ の拒否は切り詰めを「全記録経路の停止」に変える。
  修復の入口は無い。
- **L-7**: 「無い」は新規インストールと消失を区別できない（687→2 と同型が例外なしで
  起きる）。外の証人が要る。
- **L-8**: 鍵取得に締め切りが無い（guard 配下は全判定が同じ鍵 — 直列化）。
- **L-9**: 契約を宣言しない backend（sqlite / postgresql）は読みも積みも機能しない。
  guard 有効の sqlite 構成は起動不能（`FailClosedError` → `tool_registry.rb:297-298`
  再送出で tool 登録ゼロ）。復元路は backend の契約実装（別件）。

**例外が届く経路**（v0.8 と同一 — guard の判定ごと記録・guard 起動・明示 commit
3 種・`chain_distillation`/`mmp`。`state_commit` は snapshot 先行の残余、分割 ③）。
表は試験にできず、実装時に手で確かめる。
