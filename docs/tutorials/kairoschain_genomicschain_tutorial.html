Install: one gem, one init, and Claude Code finds the server

Details · slide 3

What kairos-chain init creates

  • .kairos/: modes (L0), knowledge (L1), notes (L2), SkillSets, and the local chain .kairos/storage/blockchain.json.
  • .mcp.json in the same folder (this project only; Claude Code asks you to approve it):
{"mcpServers": {"kairos-chain": {"command": "kairos-chain",
  "args": ["--data-dir", "/abs/path/.kairos"]}}}

Data directory, highest priority first: --data-dir, KAIROS_DATA_DIR, ./.kairos.

For all your projects instead: claude mcp add -s user kairos-chain kairos-chain -- --data-dir /path/.kairos (without -s user it registers for the current project only).

What it does not do, and what to check first

  • Ruby 3.3 or newer: the gem declares required_ruby_version >= 3.3; on 3.2 an old release without these modes is installed. Installing Ruby with rbenv: appendix B7.
  • kairos-chain must be on the PATH of the shell Claude Code starts (with rbenv: start Claude Code from a shell where rbenv is loaded).
  • It does not touch CLAUDE.md; that happens at kairos-chain mode project (slide 4).
  • The core SkillSets (dream, llm_client, synoptis) install on the first start; their tools appear after one restart.

Checked against kairos-chain 3.93.0 (Initializer#generate_mcp_json, gemspec) and claude mcp add --help.

Switch the mode by asking, then project it so all of it arrives

Details · slide 4

Why projecting matters

  • Claude Code passes an MCP server's instructions only up to a cap: 4,096 characters by default (Claude Code 2.1.280+, CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH), 2,048 in older versions; the rest is dropped.
  • Before projection kairos-chain sends a setup hint (762 characters) and then the mode.
  • Measured: for tutorial the 4,096 cap ends at line 84 of 309; its proactive section starts at line 82.
  • proactive_tutorial ends its six rules at character 2,008, inside even the older cap.
  • kairos-chain mode project writes .claude/kairos/instruction_mode.md and an @-import in CLAUDE.md; sub-agents read CLAUDE.md, not MCP instructions.
  • It runs only in a folder with CLAUDE.md, .git/ or .claude/; otherwise: "no plausible consumer project root".

Other commands: kairos-chain mode status, kairos-chain mode remove.

What it does not show

  • That the model follows every rule: a mode is guidance to the model, not enforcement.
  • The 2,048 figure comes from a GitHub issue, not from Anthropic's documentation.
  • If you projected another mode earlier, re-project after switching; set_mode reminds you.

GenomicsChain is add-on SkillSets: clone, install.sh, restart

Details · slide 7

Requirements and upgrade

  • kairos-chain 3.58.0 or newer (declared as min_core_version; older cores skip the package).
  • Gems ed25519 (builds a native extension: Xcode Command Line Tools on macOS) and json-schema; a missing one shows up only at submit time.
  • Start Claude Code once in the project first: the core SkillSets these need (synoptis, llm_client) install automatically only while no SkillSet is installed.
  • install.sh installs core, tier1, tier2, tier3 and mmp, and checks that all five are listed.
  • Upgrade: git pull, then bash install.sh --force --data-dir … (install copies; --force keeps config/).

What fails quietly

kairos-chain skillset list --data-dir DIR    # works
KAIROS_DATA_DIR=DIR kairos-chain skillset list   # works
kairos-chain --data-dir DIR skillset list    # starts the server instead;
                                             # in a terminal it waits for input

anchor_profile ships as false: the gc_*_submit tools are absent, not refusing. Only the one signing node of a deployment sets it to true.

Source: GenomicsChain_SkillSets README (§ Requirements, § Install, § Upgrade, § anchor_profile) and install.sh.

Demo: this guide becomes knowledge your agent reads next time

Details · slide 9

Steps

  1. In the project root: curl -LO https://masaomi.github.io/KairosChain_2026/tutorials/kairoschain_genomicschain_quickstart_v0.1.3.md (or download it there).
  2. In Claude Code: "Save kairoschain_genomicschain_quickstart_v0.1.3.md as L1 knowledge named kairoschain_genomicschain_quickstart." (The name keeps the version out of the entry.)
  3. Claude Code asks permission for knowledge_update; allow it. Expect SUCCESS: Knowledge created and Change recorded to blockchain (hash reference only).
  4. ls .kairos/knowledge/kairoschain_genomicschain_quickstart/ shows kairoschain_genomicschain_quickstart.md; "Run chain_status": the length grows by one block. Then delete the downloaded file.
  5. Restart Claude Code, then ask: "How do I upgrade the GenomicsChain SkillSets?"

What it does not show

  • The entry is a file in your data directory; its text is also sent to your model provider whenever the agent reads it.
  • The chain stores the hash of the text the agent submitted. Re-hashing the entry later shows whether it changed; it does not show that the guide is right.
  • Rehearsal: only step 2's tool call was run, directly (not through Claude Code), on a fresh throwaway instance: chain 1 → 2 blocks. The other steps were not rehearsed.

What is "the chain", exactly?

Appendix B2

What one block holds (from today's rehearsal)

{"type": "knowledge_update", "layer": "L1",
 "knowledge_id": "kairoschain_genomicschain_quickstart",
 "action": "create", "prev_hash": null,
 "next_hash": "b34dd8c8…",
 "reason": "rehearsal import", "timestamp": "2026-10-19T13:53:24+02:00"}

The block stores hashes of the content before and after, not the content itself. Each block also stores the hash of the previous block.

What it is not

  • Not a cryptocurrency; no tokens, no network, no consensus.
  • Not a backup: it records that a change happened and what it hashed to.
  • Not tamper-proof against someone who rewrites the whole file; it makes an edit to history visible, and chain_verify checks the links.

One data directory per project, or one shared?

Appendix B3

This tutorial: one data directory per project

  • kairos-chain init in each project; each gets its own notes, knowledge, chain and mode projection.
  • Projects do not see each other's knowledge.

Shared: several projects, one directory

  • Possible: point each project's .mcp.json at the same --data-dir; knowledge accumulates in one place.
  • But the mode projection is recorded in the data directory, not per project. After mode project in one project, the server treats the others as projected too, and a project without its own CLAUDE.md import gets no mode body.
  • Projected hooks find a shared directory only from kairos-chain 3.93.0.
  • This tutorial does not cover that setup.

Installing Ruby with rbenv on macOS and Linux

Appendix B7

macOS (Xcode Command Line Tools, Homebrew; zsh)

# already installed? brew upgrade ruby-build
brew install rbenv ruby-build
echo 'eval "$(rbenv init - zsh)"' >> $HOME/.zshrc

Ubuntu / Debian (bash)

sudo apt install -y git build-essential libssl-dev \
  libyaml-dev zlib1g-dev libffi-dev libreadline-dev
git clone https://github.com/rbenv/rbenv.git $HOME/.rbenv
git clone https://github.com/rbenv/ruby-build.git \
  $HOME/.rbenv/plugins/ruby-build
echo 'eval "$($HOME/.rbenv/bin/rbenv init - bash)"' >> $HOME/.bashrc

Both

exec $SHELL -l
rbenv install -L | grep -x 3.4.10  # must print 3.4.10
rbenv install 3.4.10               # several minutes
rbenv global 3.4.10 && ruby -v

Why rbenv, and what to watch

  • The Ruby an OS ships is often older than 3.3 (macOS 14 ships 2.6.10, and gems need sudo there). rbenv installs a separate Ruby the same way on macOS and Linux, without sudo for gems.
  • Install 3.4.10: the version these slides were checked on. 3.4.11 (the latest 3.x release) and Ruby 4.x have not been tested with kairos-chain.
  • If 3.4.10 is not printed, ruby-build is too old: brew upgrade ruby-build or git -C $HOME/.rbenv/plugins/ruby-build pull. -L lists every version; -l shows only the latest of each series.
  • Linux: the apt package of rbenv is often too old to know recent Ruby releases; the git install avoids that.
  • A project with a .ruby-version pinning another Ruby will not find kairos-chain unless the gem is installed under that Ruby too.
  • Start Claude Code from a shell where rbenv is loaded; do the build before a hands-on session.
